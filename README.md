# AI 红中麻将

这是一个可直接在浏览器中游玩的四人红中麻将，提供彼此独立的单机游戏和联机模式。单机游戏仍是 1 名真人与 3 个本地 AI，不接入大模型、不上传牌局；联机模式通过房间号实时对局，支持空位 AI、掉线托管、聊天和排行榜。电脑与手机都不需要安装桌面软件。

## 直接游玩

公开地址：<https://crplay.cn/>

已构建过项目时，双击 `启动游戏.cmd`，浏览器会打开：

```text
http://127.0.0.1:4173
```

服务只监听本机回环地址，局域网和互联网无法访问。关闭浏览器不会清除牌局；下次打开可继续。需要停止服务时，可在任务管理器结束对应的 `node.exe`，或者在手动运行服务的终端按 `Ctrl+C`。

单机游戏的积分、存档、声音设置和牌谱仍只保存在当前浏览器中，不会上传或与其他设备同步。联机模式只把实时牌局状态、聊天消息和排行榜统计发送到联机服务器。

首次从源码运行：

```powershell
# PowerShell，进入项目目录后执行
npm install
npm run build
npm start
```

开发模式：

```powershell
npm run dev
```

## 联机模式

- 使用昵称直接注册或登录，不使用密码、手机号、验证码，也不在浏览器持久保存登录密钥；刷新页面后需要重新输入昵称。
- 房主创建房间后分享 6 位房间号，最多 4 名真人进入；没有坐满时由房主直接开局，空位自动补充 AI。
- 联机大厅显示尚未开局的房间、当前玩家和剩余空位，可以直接加入；也保留手动输入房间号的方式。房间满员、牌局已经开始或房间号不存在时，会直接说明原因，不会一直转圈重连。
- 空位补的 AI 档位由房主开房时选（默认凡人）；真人掉线 30 秒或操作超时 30 秒后由 AI 接管，托管档位默认菜鸡——托管是帮你顶着别把牌打崩，不该替你打出比你还好的牌，这个档位只有管理模式能调。重连后可以取消托管。切换托管只影响自己的座位，不会重置任何人的操作倒计时（包括自己的），也不会延长抢牌窗口或清除别人已经做出的响应。
- 房主在对局中退出或掉线转托管后，房主身份会自动交给还在线的真人，不会出现「所有人卡在结算界面等一个已经走了的房主」。
- 服务器保存权威牌局状态，客户端只接收自己的手牌和公开信息；别人的暗杠只公开「暗杠了」这件事，不公开杠的是哪张牌，结算亮牌时才揭晓。不提供观战入口。
- 聊天保留最近 30 条，支持文字、通用 emoji，以及“快点快点”“这也碰？”“你太菜了”“你会不会玩？”“666”“乐乐”快捷消息。有人发言时，牌桌上对应座位会短暂冒出气泡，不用切到聊天面板也知道谁说了话。
- 操作被服务器拒绝时（未准备就开局、托管中操作、牌局已经推进等）都会在页面顶部给出明确提示。聊天、有人进出房间这类与牌局无关的变化不会让你手上正要提交的操作作废。
- 排行榜记录胜局数、总局数、胜率、七对次数、杠牌次数和中码数，依次按胜局、胜率、总局、七对、杠、码降序排列。

联机后端采用 Cloudflare Worker、Durable Objects 和 D1。房间只在状态变化时推送消息，不轮询；房间列表只在进入大厅或手动刷新时读取；AI 计时和断线托管由 Durable Object alarm 驱动，适合少量房间长期稳定运行。

所有倒计时都以服务器时间为准。房间状态里附带服务器当前时间，客户端据此校正本地时钟，设备时间不准也不会算错剩余秒数。抢牌倒计时只显示给当前可以碰杠的玩家，牌桌上不公开，避免通过谁在计时、犹豫了多久反推手牌。

本地联调需要两个 PowerShell 窗口：

```powershell
# 窗口一：联机服务器，首次运行会自动建立本地 D1 表
npm run dev:online

# 窗口二：网页
npm run dev
```

本地网页会自动连接 `http://127.0.0.1:8787`。如果联机服务器使用其他地址，可复制 `.env.example` 为 `.env.local`，再修改 `VITE_ONLINE_API_BASE`。

## 管理入口

用来删除用户和清理排行榜，默认关闭：**没有配置管理密钥时，管理接口完全不存在**，任何人访问都只会拿到 404。

启用方式（只需做一次）：

```powershell
npx wrangler secret put ADMIN_TOKEN --config server/wrangler.jsonc
```

按提示粘贴一串足够长的随机密钥（建议 32 位以上）。也可以在 Cloudflare 控制台的 Workers → ai-red-mahjong-online → Settings → Variables and Secrets 里添加同名 Secret。密钥只存在 Cloudflare，不进仓库、不进网页代码。

用法：在网址后面加 `#admin`（例如 <https://crplay.cn/#admin>），输入密钥进入。页面上没有任何指向它的链接或按钮，普通玩家不会碰到。

- **用户与排行榜**：清空某人的战绩（账号保留）、删除某人（账号连同全部对局记录一起消失）、一次性清空所有人的排行榜数据。
- **房间**：看到服务器上全部房间（等待中和进行中都有），可以强制解散。解散会把里面的人直接踢出去，他们会收到「房间已被管理员关闭」而不是莫名其妙的断线。
- **联机设置**：调托管 AI 的档位；开维护模式后停止创建新房间并显示自定义提示，已经在打的牌局和重连都不受影响。
- **操作记录**：删除和解散都不可撤销，面板里留了最近 100 条操作的时间和对象，方便回头查。
- 密钥只保存在当前标签页，关掉就没了；换设备或换标签页都要重新输入。
- 密钥错误和接口未启用返回的是同一个 404，从外面看不出这里有没有管理入口。
- 密钥只能通过请求头发送，不接受写在网址里，避免跟着链接或浏览器历史泄露。

本地联调时把密钥写在项目根目录的 `.dev.vars`（该文件已被 git 忽略）：

```text
ADMIN_TOKEN=你的本地测试密钥
```

## Cloudflare 部署

推送到 `main` 后，GitHub Actions 会按顺序执行测试、联机服务器类型检查、Worker 构建、D1 迁移、Worker 部署、网页构建和 Pages 部署。网页构建时会自动使用本次 Worker 的部署地址，不需要在源码中写死服务器网址。

仓库需要配置以下 GitHub Actions secrets：

- `CLOUDFLARE_ACCOUNT_ID`
- `CLOUDFLARE_API_TOKEN`：除原有 Pages 权限外，还需要 Workers Scripts 和 D1 的编辑权限。

管理密钥 `ADMIN_TOKEN` 不走 GitHub，用 `wrangler secret put` 单独配置一次即可，后续部署不会覆盖它。

Wrangler 会按 `server/wrangler.jsonc` 中的名称创建或复用 `ai-red-mahjong` D1 数据库。手动部署前先登录 Wrangler，然后执行：

```powershell
npm run deploy:online
```

## 游戏功能

- 112 张牌：万、筒、条各 1～9 四张，加 4 张红中。
- 仅允许自摸；支持普通胡和未副露七对。
- 红中可作万能牌，但不能碰、明杠、暗杠或补杠。
- 不吃牌；碰和明杠不按座次，也不设杠高于碰。同一张牌最多只有一家能碰或杠（四张同牌凑不出两家各两张），所以不存在抢先冲突。
- 刚碰完手上还留着第四张时可以直接补杠，不必等下一次摸牌；暗杠仍然要摸牌之后才能开。
- 四家各投两枚骰子，唯一最高者首庄；后续赢家坐庄，流局留庄。
- 每局固定预留最后 6 张码牌，正常摸牌和杠后补牌不会碰到码区。
- 有红中胡时抓 4 张码，无红中胡时抓 6 张；1、5、9、红中算码。
- 自摸向另外三家各收 1 分，每中一码再向三家各收 1 分。
- 暗杠、补杠向另外三家各收 1 分；明杠只向出牌者收 1 分。杠分即时结算并保留。
- 有限积分支持四家分别设置初始积分；有人积分归零立即结束整场，支付不会出现负数。
- 无限模式不设破产，只记录每人的本场净分。
- 三个 AI 只需各选一个智能档位（菜鸡／凡人／猿神），开局前或对局中都能切换，下一次决策立即生效。
- 开局页直接提供玩法规则入口和三档 AI 选择；对局中也可随时查规则或调整档位，但牌桌不展示 AI 的判断过程。
- AI 只读取自己的手牌、公开副露和牌河，不读取其他玩家暗牌。
- 四家的弃牌按方位堆在牌桌中央，和真牌桌一样；最后打出的那张会高亮，牌河堆满也一眼能找到。
- 别人的暗牌只显示还剩几张，不画十三张牌背——牌背没有信息，省下的地方留给牌河和自己的手牌；结算亮牌时才摊开。
- 牌桌上不显示任何一家 AI 的性格和智能档位，只标「托管中／离线」这类状态；想查 AI 配置在左侧信息栏里看。
- 自己摸牌后会把新摸牌单独放在手牌右侧并标注“刚摸”，顶部提示也会显示具体牌名。
- 手机竖屏顶栏只留最常用的按钮和房间号，其余收进「⋯」菜单；轮到自己时整张牌桌会透一层光。
- 四家座位统一是同样大小的方块：对家在上方居中，左右两家在两侧，牌河和对局信息居中。
- 横屏时牌桌右上角有全屏按钮，点开后收起顶栏和两侧面板，牌桌和手牌都会明显变大，再点一次或按 Esc 退出。
- 对局音乐以及摸牌、出牌、碰、杠、胜负等音效均由浏览器本地生成，默认音量拉满，可分别调节或一键静音，不访问网络。手机切到别的应用再切回来，音频会自动恢复，不需要刷新页面。
- 当前牌局自动保存在浏览器本地；支持继续上次牌局、完整步骤回放、牌谱明牌模式、JSON 导出和删除。
- 规则、投骰、积分流水、胡杠码统计和整场排名均在界面中可查看。

## AI 设计

AI 不依赖联网模型，**只有智能档位一个维度**。原来的「性格」和「速度」都并进来了：打什么牌型由 AI 看着手牌自己定，想多久由这手牌好不好打决定。

核心是**向听数**（距离听牌还差几步，红中按万能牌参与计算）和**有效进张**（还剩多少张牌能让进度前进一步，按已经看得见的牌扣减）：先比向听，再比进张，最后才用牌型偏好和保留价值微调。碰、杠用同一把尺子衡量——只有副露之后进度不倒退才动手，不会为了三分杠掉自己的听牌。

**路线由 AI 自己挑**：副露快攻、门清做对、弃红中搏码（无红中胡多抓两张码）三条路线，按当前手牌评估该走哪条。一旦副露就回不了门清，这条「已投入成本」天然提供惯性，不会出现这手做七对、下一手改门清的精神分裂。

三档的差别：

| | 菜鸡 | 凡人 | 猿神 |
|---|---|---|---|
| 向听数计算 | ✓ | ✓ | ✓ |
| 按已见牌扣减剩余张数 | ✗ 算不清 | ✓ | ✓ |
| 有效进张 | 只看手牌附近 | 完整 | 完整 |
| 一向听前瞻（进完能听多宽） | ✗ | ✗ | ✓ |
| 听牌张数最大化 | ✗ | ✗ | ✓ |
| 牌墙见底时收手保杠分 | ✗ | ✗ | ✓ |
| 碰杠判断 | 凑够就碰、有杠就杠 | 比进度 | 比进度＋杠分 |
| 顺手打错牌 | 约 45% | ✗ | ✗ |

实测 260 局（换座位复核）人均净分：猿神 +74，凡人 +5.5，菜鸡 −39.8；单步决策最长 36ms，在联机 Worker 的预算内。

**思考时间**跟着牌面走，没有速度档位：孤张一眼就扔，听牌、能胡、能杠这些要算账的地方才慢下来。实测平均思考时间——听牌 3.1 秒、一向听 2.1 秒、二向听 1.5 秒、三向听 1.3 秒。

每次出牌都会先进入抢牌响应阶段。无人可碰杠或所有候选人提前选择过时，仍会随机停留 1.2～1.8 秒后再由下家摸牌，避免通过瞬间摸牌判断其他玩家手牌。默认抢牌窗口为 4 秒，开局时可在 2～7 秒之间调整；AI 的抢牌反应按窗口独立缩放并保证在截止前完成，不再直接套用普通出牌等待时间。

## 游戏流程

```text
开局设置 → 四家投骰定首庄 → 发牌并预留六码
→ 庄家先出牌 → 弃牌抢碰/抢杠窗口
→ 无人抢则下家摸牌 → 判断自摸/暗杠/补杠 → 出牌
→ 自摸后抓码并结算 → 赢家坐庄进入下一局
→ 流局留庄；有限模式有人归零则整场结束
```
