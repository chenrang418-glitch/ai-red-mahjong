# 武将立绘接入规程

给接手的人：座位的立绘基础设施已经做完并验证过，**当前一张素材都没有**。
拿到合法素材后照这份文档做，一个武将大约十分钟。

---

## 0. 素材来源：由用户提供

**不要自己去网上抓三国杀立绘。**

早期原型用过 `KelvinQQ/SgsSkin` 的图，该仓库没有 license 文件、内容是游卡官方美术的
再分发。用户看过效果后**决定停用并自行提供素材**，那批图已从项目移除，一张都没有提交。

接手时：素材只从用户给的渠道来。如果手头没有素材，**就不要动这一块**——
没登记的武将会自动回退到国风文字底纹，不报错也不白屏，可以无限期等下去。

## 1. 素材规格（给生成软件用）

### 一句话版本

**720×960（3:4 竖构图）的半身像，脸在画面上部、宽度占画面 25% 以上，
背景简单，无文字无边框，导出 360×480 的静态 WebP，文件名 = characterId。**

### 为什么是这些数字

座位在六种情形下的实际尺寸差别很大，立绘是铺满座位的，所以同一张图会被裁成
从「几乎完整」到「只剩一条横带」的各种样子。按 3:4 源图算，各档能看到原图的比例：

| 情形 | 座位尺寸 | 纵向可见 | 横向可见 |
|---|---|---|---|
| PC 其他座位 | 190×142 | 56% | 100% |
| **PC 自己座位** | 280×120 | **32%** | 100% |
| 竖屏 其他座位 | 90×118 | 98% | 100% |
| 竖屏 自己座位 | 173×106 | 46% | 100% |
| 横屏 其他座位 | 138×94 | 51% | 100% |
| 横屏 自己座位 | 160×90 | 42% | 100% |

**最苛刻的是 PC 自己座位：只剩 32% 的纵向高度。**
所以脸周围必须有余量，脸贴着画面顶边的构图一裁就没。

脸要多大？竖屏最小座位只有 90px 宽，按移动端倍率 1.15 换算：

| 脸占原图宽度 | 屏幕上的脸 |
|---|---|
| 15% | 16px —— 看不清是谁 |
| 20% | 21px —— 勉强 |
| **25%** | **26px —— 下限** |
| 30% | 31px —— 舒服 |

**这条决定了必须是半身像，不能是全身站姿。**
原型阶段试过一张全身立绘，脸只占画面 12%，在手机上完全认不出来，
只能靠把倍率拉到 3.2 硬放大，结果画质糊掉。

### 硬性要求

| 项 | 要求 |
|---|---|
| 比例 | **3:4 竖构图**（如 720×960、1080×1440） |
| 源图尺寸 | 短边 ≥ 720px（要下采样到 360px 宽，留余量） |
| 交付格式 | **静态 WebP**，360px 宽。**不接受 GIF / 视频 / 动态 WebP** |
| 单张体积 | ≤ 40 KB |
| 文件名 | 必须等于 characterId（见下表），如 `zhaoyun.webp` |
| 放置位置 | `src/sanguosha/assets/characters/portraits/` |

导出命令（一次性脚本放项目根目录跑，放 scratchpad 里找不到 `sharp`）：

```js
import sharp from 'sharp'
await sharp(src).resize({ width: 360 }).webp({ quality: 82, effort: 6 }).toFile(dst)
```

### 构图要求

1. **半身像**：头到胸口或腰部，**不要全身站姿**
2. **脸宽 ≥ 画面宽度的 25%**，建议 30%
3. **脸的中心**：横向 45%~60%，纵向 18%~28%
4. **头顶留白 ≥ 8%**，脸不要贴边——PC 自己座位只剩 32% 高度，贴边必被裁掉
5. **背景简单**：纯色、渐变或虚化都行。复杂背景在 90px 宽的座位上只会变成噪点
6. **无文字、无边框、无水印、无技能说明**
7. **整批画风统一**：混入风格差异大的一张，在牌桌上一眼就能看出代差

### 背景明暗不用担心

文字可读性靠**描边**保证，不靠压暗遮罩——描边是局部生效的，不看背景亮度。
原型阶段实测过亮度从很暗到很亮的六张图，白字裸对比度 2.7:1 到 8.3:1 都有，
加描边后都读得出。**所以背景是深是浅都可以，按好看来就行。**

## 2. 登记裁切参数

在 `src/sanguosha/assets/characters/manifest.ts` 的 `FRAMING` 里加一项：

```ts
zhaoyun: {
  desktop: { position: '52% 20%', scale: 1.0 },
  mobile:  { position: '52% 18%', scale: 1.15 },
  credit:  '<素材出处，便于回溯授权>',
},
```

**`position` 就是脸在原图里的位置**（横向%、纵向%）。它同时喂给 CSS `object-position`
和 `transform-origin`——焦点定「看哪儿」，倍率定「多近」，两个参数不打架。

### 倍率的经验区间

立绘**铺满整个座位**，而座位比常见立绘更矮更宽，所以：

- `1.0` 已经是裁掉上下、露出中段，**竖构图立绘的默认值就是它**
- 横构图原图（宽 > 高）用 `1.05`
- 移动端统一比 PC 高一档：`1.15`（竖构图）/ `1.20`（横构图）

### 纵向焦点的经验区间

- 竖构图站姿：PC `18%~22%`，移动端比 PC 小 2 个百分点
- 横构图：脸通常在中段，`38%~42%`
- 移动端焦点略上移，是因为座位更矮，往上给才留得住脸

**具体数值必须对着浏览器调，没有通用公式。**
不要把任何武将的数值写进 `SgsSeat.vue`，组件只负责把参数变成 CSS 变量。

## 3. 座位的四层结构（改样式前必读）

```
1  .sgs-seat__portrait   势力底色 + 无图时的文字底纹
2  .sgs-seat__art        独立 <img>，铺满座位
3  .sgs-seat__shade      有图时不压任何遮罩（--art 时 background:none）
4  信息层                z-index 2，姓名 / 身份 / 血量 / 装备 / 技能
```

用独立 `<img>` 而不是 `background-size: cover`，是因为位置、缩放、灰度、阵亡态
需要分别控制，背景图给不了这个自由度。

### 三条不能碰的约束

**① 立绘层必须有自己的裁剪容器。**
`.sgs-seat__art` 是 `overflow:hidden` 的 div，`<img>` 在里面做 `transform: scale()`。
不能把 scale 直接加在座位的直接子元素上——放大溢出的部分会算进座位的 `scrollHeight`，
E2E 的「角色卡内容不能被座位高度裁切」会误判成信息放不下。**这个坑踩过一次。**

**② 文字靠描边，不靠压暗。**

早期用六张真实立绘量过文字区亮度，白字裸对比度从 **2.7:1 到 8.3:1** 都有，
最亮的两张低于可读线 4.5:1，而且每张图都有纯白高光，局部还会更低。

结论：**压暗遮罩救不了**——压轻了亮图读不出，压重了整张画糊掉，
而且遮罩会把脸推到边缘。**描边是局部生效的、不看背景亮度**，所以能兜住任意立绘。
这是满幅方案唯一能成立的原因。

`.sgs-seat--has-art` 那一段是通用的，**加新武将不需要为它单独调文字**。

**③ 断点要跟座位布局对齐。**
`@media (max-width: 820px), (orientation: landscape) and (max-height: 500px)`。
只写 `max-width: 820px` 会漏掉手机横屏——那是 932 宽却只有 94px 高的座位，
拿 PC 参数会让脸太小。

## 4. 状态

已经做好了，加新武将不用动：

| 状态 | 表现 |
|---|---|
| 当前行动 | 立绘 `saturate(1.12) brightness(1.06)`，金色边框照旧 |
| 选中目标 | 立绘 `brightness(.82)` 压暗，让红色高亮边框先被看到 |
| 阵亡 | **只有立绘**变灰变暗（`grayscale(1) brightness(.42)`），座位仅 `opacity:.76`，身份血量仍可读 |

阵亡态原来是给整个座位加 `grayscale + opacity:.58`，把身份和血量一起糊掉了，已改。

## 5. 验收清单

加完一个武将，**至少**在这三档看过：

| 尺寸 | 重点 |
|---|---|
| PC 1440×900 | 脸是否清楚、是否与其余立绘协调 |

| 手机横屏 932×430 | 座位只有 94px 高，最容易把脸裁没 |

**8 人局必须单独看一遍**，人越多座位越小。

## 6. 已知问题（不是立绘引起的，别当成自己改坏了）

**横屏 8 人局在底部面板变高时座位会重叠。**
环形槽位按牌桌区高度的百分比定位，而座位高度是固定 `clamp()` px。
五谷丰登亮出 8 张牌时面板涨到 138px，牌桌区被压到 255px，
上下两槽间距只剩 79px，装不下 94px 的座位 → 吕布×张飞、关羽×赵云各叠 15px。

**把立绘整个关掉重测，重叠一模一样**，是既有布局问题。修它要动 `SgsSeatLayout` 的
定位方式（百分比改成基于座位高度计算），不在立绘范围内。
