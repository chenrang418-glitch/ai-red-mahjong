# 夺锐兼容性

神张辽【夺锐】可以临时夺走目标武将牌上的一个技能。这份文档记录**哪些技能可以被夺、
哪些不行、以及为什么**，并由 `npm run sanguosha:duorui-audit` 自动校验。

## 判定原则

**只读运行时元数据，不用武将 id 黑名单。** 和左慈【化身】的资格判定同一条原则：
普通技能默认可夺，只有明确的规则冲突才排除。

如果某个理论上合法的普通技能因为实现里写死了武将 id 而不能被夺，
**那是引擎的 bug**，要去修那个技能的拥有者判断，不是在排除表里加一行。

## 当前结果（2026-09-04 实测）

```
可夺的普通技能：124
排除的技能：25
  - 主公技：8
  - 觉醒技：5
  - 不在武将牌上（觉醒后才获得的条目）：5
  - 限定技：4
  - 与左慈的化身池强绑定，换人持有无对应资源：1   （化身）
  - 依附【化身】而存在，脱离化身池无意义：1        （新生）
  - 夺锐期间不能再发动夺锐，夺取它本身没有意义：1  （夺锐）

不兼容的可夺技能：0
```

## 排除的依据

| 类别 | 依据 | 说明 |
|---|---|---|
| 限定技 | `SkillRuntime.limited` | 表述明确排除 |
| 觉醒技 | `SkillRuntime.awakening` | 表述明确排除 |
| 主公技 | `SkillRuntime.lord` | 表述明确排除 |
| 觉醒后才获得的条目 | `skill.granted` | 不印在武将牌上，不是夺锐的候选 |
| 规则冲突 | `skill-theft.ts` 的 `STRUCTURAL_EXCLUSIONS` | 逐条写明原因，见下 |
| 技能自己声明 | `SkillRuntime.stealable === false` | 留给将来的特例，目前没有用到 |

**注意**：「觉醒后才获得的条目」排除的是武将牌上那一行 `granted` 标记的条目，
不是「通过觉醒拿到的技能本身不可夺」——技能能不能被夺看它**自身的类型**，
和它是怎么来的无关，这一点和化身同理。

### 规则冲突的三条

| 技能 | 原因 |
|---|---|
| 化身（左慈） | 与左慈的化身池强绑定，换人持有没有对应资源 |
| 新生（左慈） | 依附【化身】而存在，脱离化身池无意义 |
| 夺锐（神张辽） | 夺锐期间本来就不能再发动夺锐，夺取它本身没有意义 |

神司马懿【极略】不在这张表里：它在武将牌上是 `granted` 条目（觉醒后才获得），
已经被前一条规则排除。它同样依附「忍」这项资源，换人持有没有来源。

## 审计做了什么

对每一个「可夺」的技能：

1. 临时授予给神张辽、同时压制目标的同名技能
2. 确认目标确实失去了它、神张辽确实拿到了
3. 序列化往返一次，确认重连之后两边都还成立
4. 逐个调用 `activeActions` / `viewAs` / `maxCardsBonus` / `retrial` / `multiCardViewAs`，
   确认不会因为实现里写死武将 id 而抛错
5. 解除之后确认两边都不残留

审计**跳过神张辽自己武将牌上的技能**：夺锐的目标必须是其他角色，
而普通武将一桌只会出现一个，所以「夺到自己也有的技能」在规则上不可达。
不跳过的话会误报「解除后仍残留」——残留的是他自带的那一份。

## 一个真实踩到的坑

夺走**支撑对方在 0 体力存活的技能**（周泰【不屈】）时，对方必须立刻重新进入濒死，
否则会留下「0 血非濒死存活」的非法状态（压测 seed=balance-5-105）。
反过来，夺锐**到期**时神张辽自己失去夺来的【不屈】，同样要重新检查
（压测 seed=soak-8-33）。

两边都走公共入口 `recheckZeroHpAfterSkillLoss`——左慈换化身、蔡文姬【断肠】
踩的是同一个坑。现在 `Game.settle()` 里有一道统一兜底，
在场面完全干净时扫一遍所有 0 体力却仍存活的角色。
